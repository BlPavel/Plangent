# Подключения и справочники документации

Эта инструкция открывается кнопкой «Как настроить» в форме подключения и в форме справочника типа «Документация». Для первого подключения используйте раздел 2; для другого сервиса — разделы 5–7.

## 1. Что вы настраиваете

**Организация** объединяет подключения одной компании и позволяет назначить общую учётную запись. Необязательна: для одного сервиса можно сразу создать подключение.

**Учётная запись** хранит логин и пароль. Одна общая запись может использоваться несколькими подключениями. Пароль вводится отдельно, после сохранения не показывается.

**Подключение** задаёт корень сервиса, способ входа и проверку текущего пользователя. Режим «От организации» использует общую запись организации; «Другая запись» — выбранную запись этой организации; «Свой логин и пароль» — отдельные данные только для подключения.

**Справочник типа «Документация» (docs)** использует подключение и описывает, как получить страницы, разобрать ответ и выбрать разделы. Один и тот же сервис может обслуживать несколько справочников с разными разделами.

Корень подключения — протокол, домен и при необходимости порт: например, https://confluence.ru.mgo.su. Ссылка на страницу https://confluence.ru.mgo.su/pages/viewpage.action?pageId=283673173 нужна для добавления раздела, а не вместо корня.

Пути входа и скачивания относительны к одному корню:
- /dologin.action → https://confluence.ru.mgo.su/dologin.action;
- /rest/api/content/{id} при id 283673173 → https://confluence.ru.mgo.su/rest/api/content/283673173.

Если сервис установлен под https://host/wiki, корень — https://host, а каждый путь входа, проверки, документа, списка, поиска и оригинала должен начинаться с /wiki/. Запросы и перенаправления на другой домен не поддерживаются.

«Заполнить как» копирует настройки шаблона в форму. Их можно менять; последующее обновление шаблона не изменяет уже сохранённые настройки.

## 2. Первый запуск: Confluence Server/DC

Потребуются доступ к серверу (включая VPN, если он нужен), рабочий логин/пароль и право читать нужную страницу. Пример ниже показывает адрес сервиса и страницы; используйте собственную учётную запись.

1. Откройте «Настройки» → «Подключения» → «+ Подключение».
2. Назовите подключение, например «Вики компании».
3. В «Корень сервиса» укажите https://confluence.ru.mgo.su. Если вставили ссылку на страницу, воспользуйтесь предложением «Обрезать до корня».
4. Выберите «Заполнить как: Atlassian Server/DC». Шаблон задаёт автоматический перебор Basic, затем формы входа, путь /dologin.action и проверку /rest/api/user/current.
5. Для первого подключения выберите «Свой логин и пароль», введите данные, сохраните. Если пароль задан, приложение проверит подключение после сохранения. Повторную проверку запускайте кнопкой «Проверить» в списке.
6. Убедитесь, что результат сообщает об успешном входе и показывает пользователя. Проверьте, что это ваша запись. URL под результатом показывает адрес выполненной проверки.
7. Создайте новый справочник. Выберите тип «Документация», задайте название и уникальный ключ, например wiki.
8. Выберите «Вики компании» и «Заполнить как: Confluence Server/DC». Это отдельный шаблон: он задаёт получение документов, дерево и преобразование текста.
9. В поле ссылки или id вставьте https://confluence.ru.mgo.su/pages/viewpage.action?pageId=283673173. Нажмите «Проба запросом»: проверьте URL, найденные поля и предпросмотр текста.
10. Нажмите «Добавить раздел». Можно вставить только 283673173. Для загрузки раздела целиком оставьте включённым выбор дочерних документов; для одной страницы выключите его.
11. Откройте дерево, если нужно исключить ветки. Исключение убирает страницу и её потомков из загрузки; повторное включение возвращает ветку. Пересекающиеся разделы не создают дубликатов.
12. Сохраните справочник, откройте его и нажмите «Обновить». Дождитесь завершения и проверьте итог: новые, обновлённые, удалённые, без изменений и ошибки.
13. Сделайте справочник доступным нужному проекту через «Доступны для». В задаче упомяните @wiki и попросите агента прочитать INDEX.md и нужные страницы.

Шаблоны рассчитаны на Confluence Server/Data Center с обычным входом и REST API. Для Cloud, SSO, MFA или входа через внешний портал готовый сценарий может не подойти. Вход в браузере сам по себе не авторизует Plangent: приложение получает собственную сессию.

## 3. Общая учётная запись

Для нескольких сервисов одной компании:
1. Создайте организацию.
2. Создайте учётную запись в этой организации, укажите логин и пароль.
3. Откройте организацию повторно и выберите созданную запись как общую.
4. В подключениях выберите эту организацию и режим «От организации».

Если сервису нужна другая запись, создайте её в той же организации и выберите «Другая запись». Собственный пароль подключения меняется только для этого подключения; пароль общей записи меняется один раз для всех использующих её подключений.

Пустое поле пароля при редактировании означает «оставить сохранённый пароль». Оно не показывает старое значение.

## 4. Синхронизация и локальные файлы

«Обновить» запускает синхронизацию выбранных разделов. Сначала приложение один раз обходит дерево и сравнивает версии с уже скачанными страницами, затем загружает новые и изменённые документы. Интерфейс показывает общее число найденных страниц и сколько требуется загрузить. Подтверждение нужно, если загрузить требуется больше 500 документов; после него повторного обхода нет. Список для подтверждения хранится 10 минут. Если он устарел или настройки изменились, нажмите «Обновить» заново.

Закрытие карточки справочника не отменяет работу сервера. Для остановки используйте «Отменить синхронизацию». После перезапуска приложения прерванную синхронизацию нужно запустить снова. Пока она идёт, менять выбор разделов нельзя.

Повторная синхронизация использует версии страниц. Если версий нет, текст скачивается для сравнения; если нет отдельного запроса метаданных, проверка изменений тоже требует загрузки документа.

Агенты читают локальные Markdown-файлы и INDEX.md, содержащие оглавление и краткие фрагменты. Пароли агентам не передаются. Последняя загруженная копия доступна офлайн, но без сети не обновляется. Изображения остаются ссылками на сервер и могут требовать сеть и вход.

При ошибке обхода или отмене до публикации прежние файлы сохраняются. Ошибка отдельной страницы сохраняет её прежнюю копию, остальные документы могут обновиться: проверьте число ошибок и «Подробнее». Файлы больше не выбранных или исчезнувших документов удаляются при успешной публикации. Не редактируйте управляемую копию как собственный архив: последующее обновление может её заменить.

## 5. Как узнать параметры другого сервиса

Начните с документации API сервиса или спросите администратора о поддержке Basic/формы входа и JSON API документов. Одной ссылки на сайт недостаточно.

В браузере:
1. Откройте страницу входа. Нажмите F12 и перейдите на вкладку «Сеть» (Network).
2. Выполните обычный вход. Найдите POST-запрос, появившийся при нажатии «Войти».
3. Из Request URL возьмите путь без корня. В Payload / Form Data найдите имена полей логина и пароля, например username и password. Нужны имена, а не введённые значения.
4. Если форма передаёт постоянные дополнительные параметры, запишите только публичные константы. Не копируйте пароли, Cookie, Authorization, токены и временные защитные значения в настройки.
5. Откройте страницу документа и найдите запрос, возвращающий его JSON. Во вкладке Response посмотрите id, заголовок, текст, версию, родителя и список дочерних страниц.
6. Найдите запрос текущего пользователя (me/current user/whoami). Он должен подтверждать вход, а не отдавать общедоступную страницу.

Если вход требует динамический CSRF-токен, JavaScript, SSO, MFA или отдельный домен авторизации, простая форма может быть несовместима. Уточните у администратора возможность поддерживаемого доступа. Режимы входа через браузер и токен сейчас не реализованы.

## 6. Ручная настройка подключения

Раскройте «Параметры входа». Настройки полей и «JSON целиком» редактируют одни и те же данные; неверный JSON нужно исправить перед сохранением.

| Поле | Что указать |
| --- | --- |
| Способ входа | Basic — если API принимает логин/пароль; форма — если сервер принимает POST и выдаёт cookie; автоматически — перебор basic, form в указанном порядке |
| Путь проверки «кто я» | Относительный путь API текущего пользователя, например /api/me |
| Поле имени в ответе | Путь в JSON, например user.name; пустое значение оставляет проверку без извлечения имени |
| Ответ должен быть JSON | Включите для JSON API: HTML страницы входа тогда не считается успехом |
| Путь для входа | POST-путь формы, например /login |
| Имя поля логина / пароля | Имена из Form Data, например username / password |
| Дополнительные поля формы | Публичные постоянные параметры по одному «имя: значение» в строке |
| Заголовки запросов | Публичные постоянные заголовки; секреты сюда не вставляйте |
| Ожидание ответа, мс | Обычно 15000; можно увеличить для медленного сервера/VPN |

Признаки «Неверный пароль» и «Сессия истекла» могут задаваться кодами HTTP, именем и значением заголовка, путём перенаправления (со звёздочкой) или HTML вместо JSON. Заполняйте их по документации сервиса. Признак неверного пароля останавливает попытки входа до обновления пароля; признак истёкшей сессии допускает повторный вход. Не назначайте общий сетевой сбой или запрет доступа признаком неверного пароля.

Сохраните подключение и нажмите «Проверить». Сверьте итоговый URL с ожидаемым запросом и проверьте пользователя.

## 7. Ручная настройка docs-справочника

Выберите подключение и раскройте «Настройки источника». Нужен JSON API с устойчивым id, заголовком и текстом документа в HTML или Markdown.

| Настройка | Назначение |
| --- | --- |
| Путь документа | Например /api/pages/{id}; {id} подставляется из выбранной страницы |
| Путь метаданных | Необязательный более лёгкий запрос версии и структуры |
| document_path / metadata_path в JSON целиком | Путь к объекту документа, если ответ обёрнут, например payload |
| Поля id, title, body | Пути к идентификатору, заголовку и тексту внутри объекта документа |
| version | Номер/метка версии для проверки изменений |
| parent / ancestors | Родитель или массив предков для структуры локальных файлов |
| updated / space / author | Дата, пространство и автор для шапки файла |
| url / ссылка на оригинал | Поле ответа со ссылкой либо шаблон /pages/{id} |
| Формат текста | HTML или markdown согласно ответу API |
| Дочерние документы | Путь списка непосредственных потомков и путь к массиву, например results |
| Постраничная загрузка | offset с именами параметров смещения/размера либо next с путём следующей ссылки |
| Поиск по заголовку | Нужен для ссылок без id; запрос с {title} и {scope} должен вернуть ровно один документ |
| Шаблоны ссылок | Регулярное выражение и номер группы с id (id_group, начиная с 1); для названия — title_group и scope_group |

Путь через точку означает вложенное поле: body.storage.value — value внутри storage внутри body. Поля документа считаются относительно document_path, если он задан. Путь списка children.items_path считается относительно ответа списка. Для числового индекса массива используется точка, например results.0.id.

Минимальный пример для условного сервиса, возвращающего {"id":"42","title":"Начало","body":"# Привет"}:

```json
{
  "document_endpoint": "/api/pages/{id}",
  "fields": { "id": "id", "title": "title", "body": "body" },
  "body_format": "markdown",
  "original_url": "/pages/{id}",
  "link_patterns": [
    { "pattern": "/pages/([0-9]+)", "id_group": 1 }
  ]
}
```

Это пример структуры, а не готовый шаблон вашего сервиса. Без children выбор загружает только указанные страницы; без version текст сравнивается целиком. Для API с выдачей списков порциями настройте пагинацию, иначе часть дерева останется за первой порцией. Размер страницы для offset — от 1 до 1000; имена параметров возьмите из запроса браузера.

Для HTML можно настроить упорядоченные правила преобразования особых элементов: selector — CSS-селектор; action — code (код), callout (примечание), unwrap (содержимое без оболочки), skip (пропуск), unknown (пометка). content выбирает содержимое, parameter — язык/метку. Срабатывает первое подходящее правило. Обычные заголовки, списки и таблицы обрабатываются без специальных правил.

### Проверка «Проба запросом»

До сохранения вставьте id или ссылку и нажмите «Проба запросом». Она не публикует файлы. Проверьте:
1. URL соответствует выбранному корню и нужному документу.
2. Поля id, заголовка и текста найдены; id совпадает с запрошенным.
3. Предпросмотр содержит нужный текст, списки и код.
4. Предупреждения об отсутствии дерева, версии или метаданных вам понятны.

Если поле не найдено, сравните путь с реальным JSON Response, исправьте настройки и повторите пробу. После успешной пробы добавьте раздел и сохраните справочник. Проба не заменяет проверку всей выбранной ветки при синхронизации.

## 8. Ошибки и восстановление

| Сообщение или ситуация | Что сделать |
| --- | --- |
| Нет связи — VPN? | Включить VPN, открыть корень сервиса в браузере, проверить адрес и доступность, повторить «Проверить» |
| Неверный логин/пароль или требуется обновление | Проверить данные и нажать «Обновить пароль»; до этого повторные попытки входа остановлены |
| Нет прав | Запросить у администратора доступ для этой учётной записи; смена пароля права не добавляет |
| Способ входа не подходит | Сверить параметры входа; уточнить SSO/MFA/поддержку Basic или формы |
| Поле не найдено в ответе | Исправить JSON-путь, обёртку объекта или путь документа; повторить пробу |
| Вместо JSON страница входа | Проверить подключение, сессию и путь API |
| Документ не найден / 404 | Сверить id и путь документа, проверить доступ к странице |
| Ссылка не подходит под шаблон | Вставить id либо исправить шаблоны ссылок |
| Поиск вернул несколько документов | Использовать ссылку с устойчивым id |
| Ссылка другого сервиса | Выбрать подключение с нужным корнем |
| Уже идёт синхронизация | Дождаться завершения либо отменить текущую |
| Повреждён manifest | Не удалять служебные файлы наугад; сохранить локальную копию и обратиться за помощью |

При смене корпоративного пароля откройте «Настройки» → «Подключения», обновите пароль нужной учётной записи (для собственного входа — подключения), затем выполните «Проверить» и «Обновить» справочника. Общая запись обновляет все зависимые подключения. Для логина и пароля нет автоматического обновления пароля как у токена: новые данные вводятся вами.

При переносе базы на другую машину или под другую учётную запись ОС старые секреты могут оказаться недоступны. Задайте пароль заново, проверьте подключение и повторите синхронизацию; перенос Markdown сам по себе вход не восстанавливает.

В установленном приложении секреты защищаются средствами ОС. Если хранилище недоступно, приложение не сохраняет пароль и не выполняет вход. В dev-режиме ключ лежит рядом с базой: это не защита от человека с доступом к папке; для рабочих паролей используйте установленное приложение.

Для обращения за помощью достаточно названия подключения, публичного URL запроса, сообщения об ошибке и списка отсутствующих полей. Не отправляйте пароль, cookie или полный дамп запроса входа.
