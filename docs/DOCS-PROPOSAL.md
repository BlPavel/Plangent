# Документация и внешние источники — предложение (на потом)

Статус: идея, не реализовано. Сейчас сделаны только **справочники-папки**
(см. «Группы и справочники» ниже); этот документ описывает, как на ту же
модель лягут документация и интеграции, чтобы потом не переделывать.

## Основная идея

Всё, на что можно сослаться через `@`, — **справочник**: глобально уникальный
ключ (`ui-kit`), необязательное описание для агента и папка с файлами.
Справочники отличаются только тем, *откуда в папке берутся файлы*:

| Тип          | Откуда файлы                                   | Кто пишет                   |
|--------------|------------------------------------------------|-----------------------------|
| Папка        | папка разработчика на диске                    | никто (только чтение)       |
| Документация | папка с `.md`, редактор внутри Plangent        | разработчик; агент — через одобрение |
| Внешний      | синхронизация (Confluence и др.) в локальный кэш | внешний сервис           |

Агент всегда видит одно и то же: ключ, описание и путь. Читает файлы своими
инструментами и только когда нужно — в контекст ничего не грузится заранее.
В БД это строка `projects` с `kind = 'source'`; тип хранится в
`config.source_type` (сейчас всегда `folder`).

## Документация (ручная)

- Справочник типа «Документация» = папка с markdown. По умолчанию в данных
  Plangent, но можно указать свою папку (например, внутри репозитория — тогда
  доки версионируются вместе с кодом).
- В Plangent у такого справочника появляется вкладка с деревом файлов и
  markdown-редактором с превью; вставка картинок кладёт файл рядом.
- Цикл: пишешь доку → ссылаешься в задаче `@arch-docs/api/auth.md` → в конце
  задачи агент может предложить обновить доку (правка в папке справочника
  идёт через одобрение с diff, даже в автономном режиме) → правки видны сразу.

## Внешние источники (Confluence и т.д.)

- **Подключения** — отдельный раздел настроек: аккаунт сервиса (URL, токен,
  прокси). Одно подключение Atlassian используется и Confluence-справочником,
  и будущим импортом задач из Jira.
- Внешний справочник = подключение + что тянуть (пространство, страница с
  дочерними, метка). Plangent выкачивает страницы в markdown в кэш-папку,
  рядом хранит метаданные (id страницы, версия, URL, время синхронизации).
- Агент читает снимок, а не API. На странице справочника — «обновлено N
  назад» и кнопка «Обновить»; позже — автообновление перед задачей, если
  снимок старше N часов.
- Обратная публикация (правки из Plangent → Confluence) — далёкое «потом»;
  метаданные версий сохраняем сразу, чтобы потом обнаруживать конфликты.

## Открытые вопросы на потом

1. Редактор: markdown + превью или визуальный.
2. Может ли агент создавать новые страницы доки или только править.
3. Confluence Cloud или Server/Data Center (разный API и авторизация).
4. Какие ещё сервисы планируются — чтобы модель подключений их выдержала.

## Группы и справочники (реализовано)

- `projects.kind`: `project` | `group` | `source`. Группа — тоже строка
  `projects`, поэтому задачи, чаты, планы и очередь работают для неё без
  отдельного кода. Рабочая папка группы — служебная папка в данных Plangent
  с `README.md`, где перечислены проекты группы и их пути.
- `projects.group_id` — группа проекта (один уровень, проект максимум в одной
  группе). `projects.key` — ключ для `@` у проектов и справочников, уникален
  глобально.
- «Доступно для» (скиллы и справочники): «Везде» или выбранные группы/проекты;
  группа включает все свои проекты, в том числе добавленные позже.
- Агент знает только каталог: ключ, описание, путь. Соседи по группе видны как
  справочники только на чтение. Запись в справочники запрещена политикой.
